# VibeRick Dub product and submission improvement plan

Prepared 2026-10-10. Investigation and proposed implementation, not a deployment or submission approval. Existing production and submission assets remain unchanged.

## Recommendation

Build an inspectable dubbing studio: **Keep your voice. Get the timing right. Fix what needs fixing.** The decisive demonstration is a real defect becoming an audibly better line, with the source, target languages, speaker turns, and actual agent decisions visible together.

The current system is a credible prototype: deployed product, timestamp-backed transcription, consent-aware voice selection, and real automatic retries. Its weaknesses are natural pacing, trustworthy timing measurements, incomplete editing, and delayed access to results. Improving those is more valuable than a nominal 100-language menu.

The official [rubric](https://aibuildercup.com/themes.html) weights technical merit 40%, impact 25%, innovation 25%, UX 10%. The [FAQ](https://aibuildercup.com/Faqs.html) requires a deployed prototype, public repository, deck, and video under three minutes, plus a 2–4-person eligible team. Preserve the mandatory deck template. Local dashboard notes record roster lock October 12 at 03:29 KST and submission October 19 at 03:29 KST; target October 17. These exact times were not independently rechecked in the authenticated dashboard during this review. Yuke's acceptance remains unconfirmed.

## Findings that change the plan

| Evidence | Implication |
|---|---|
| `dub/config.py` and `web/index.html` expose ko/en/ja/zh-Hans only | “Every language” is an ambition, not current coverage. |
| `server/app.py` exposes health and job creation only | Line editing/regeneration is not implemented; keep it out of a current-feature claim. |
| `mix.place()` returns placed starts, but `pipeline.py` discards them | Target captions and transcript can disagree with audio when lines flow early. |
| `late_p95` only measures positive lateness | Relabel it; it does not establish absolute timing drift or lip sync. |
| Full-video median clip/slot ratios: EN .798, JA .759, ZH .797 | Short speech plus repeated anchoring leaves long gaps. |
| `units.flow_gaps()` has no speaker-change guard | Moving a line early can damage interview turn-taking. |
| Output upload occurs after all languages finish | A slow or failed language withholds otherwise usable results. |
| `voice.py` sends bare transcript and voice, no delivery metadata | Structured style directions are a testable route for language/accent control. |
| Existing Demis Hassabis/Hannah Fry run has 28/28 automated passes | Two-person handling has internal evidence already; it is preset casting, not celebrity voice cloning. |

The live homepage is functional but puts a large headline and URL form above the useful player. Transcript and agent activity compete for one tabbed panel. Judges should hear an example immediately, then inspect the mechanism.

## Product work in priority order

### 1. Make timing and quality truthful

Persist a versioned output timeline per language and line: source start/end, actual dubbed start/end, speaker ID, voice type, generated duration, fitted duration, tempo, repair actions, and review status. Derive target subtitles, highlighting, exports, and the editor from those actual placements.

Keep three different measures separate: source/dub anchor error; subtitle/audio alignment error; excess silence while the original speaker is speaking. Report early and late errors separately and absolute-error percentiles. Sentence timing is not lip synchronization.

Block flow across speaker changes immediately. Detect and flag unsupported overlaps rather than silently moving replies. Protect the final clip from truncation and preserve hard scene/slide/action boundaries. A later scheduler can use independent speaker buses.

Acceptance: deterministic fixtures with early starts, speaker switches, overlapping turns, a hard scene boundary, and final-buffer overflow; captions match actual placement; no invisible clipping.

### 2. Improve rhythm with measured audio feedback

Optimize short same-speaker passages between protected anchors. Translate for meaning and natural delivery; synthesize; measure actual speech occupancy; then choose whether to rewrite, adjust tempo conservatively, or redistribute pauses inside the passage. Preserve intentional hesitation, comedic timing, breaths, and silence. Never add facts or filler simply to fill a slot.

Character budgets are a useful starting estimate, but should be calibrated by voice, language, and delivery style. Japanese mora, Chinese syllables/tones, and English stress patterns do not share a universal characters-per-second target. Technical names and mixed-script lines deserve explicit pronunciation tests. Expansion should respond to measured underfill, not only the current 60% character threshold.

Paragraph generation exists but was disabled after Japanese cut failures. Test it on bounded passages with word-boundary confidence and a sentence fallback before enabling it globally. Scene detection is proposed work, not an existing capability.

Proposed experiment target: reduce excess silence over the matched baseline by at least 30%, while native listeners prefer the result and no turn/cut boundaries are violated. This is a target, not an achieved benchmark; whole-video silence alone is insufficient.

### 3. Fix leakage at generation and retain verification

Google's current [TTS model documentation](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash-tts) says sustained directions belong in `speech_metadata.style`, while transcript text is spoken verbatim. Do not prepend “Speak Japanese” to the text. Test structured target-language/accent/style directions against the existing bare-text baseline; language is still automatically detected, so this is not a guaranteed language lock.

Test Korean-clone and preset voices across short, long, and mixed-script JA/ZH passages. Validate translation language before synthesis, then evaluate the resulting audio. Track first-pass leakage, retries, final failures, cost, and native-listener judgments. A different preset voice is a visible user choice, not a silent replacement for their clone.

The current Gemini checker compares generated speech to the expected translation. It does not independently prove that translation preserved the source meaning. Add source-to-translation adequacy review and human listening to a held-out sample.

### 4. Build the comparison and repair experience

One master video; one playhead; source and target-language lanes visible together. Only one language plays at once. Switching tracks preserves position. Clicking a segment opens source/translation, timing, voice, and real repair history. Use actual waveform samples only when measured; interval blocks must be labelled as intervals.

Implement edit → regenerate selected line → verify → audition before/after → accept version. Cache STT/separation/other languages. Keep the previous audio, update the output timeline, remix only what is needed, and regenerate subtitles. Preserve untouched segments. Handle double clicks, retries, ownership, and concurrent edits with version checks.

Show per-language progress and publish a language as soon as it finishes. A failed language must not hide successful ones. Use explicit ready, needs review, failed, and processing states.

### 5. Bound concurrency and make jobs recoverable

Languages already run concurrently, with up to eight line workers per language and a text semaphore. Increasing workers indiscriminately risks shared quotas and CPU/memory pressure. Use bounded text/TTS/FFmpeg pools, per-language fairness, project-wide rate budgeting across Cloud Run jobs, jittered retry, and durable checkpoints.

Add an independent worker heartbeat and reconcile it with execution status. A long stage without a stage-change event is not proof of failure. Validate finite positive clip length; classify retryable failures; retry malformed model JSON inside the bounded retry loop. Revisit daily caps with atomic admission controls before adding broad access.

Measure cold cloud completion, warm completion, first playable language, and stage latency separately. Credits offset payment; they do not make compute/storage/proxy use economically free. The deployment is not wholly Seoul: `STT_LOCATION` is `us`, and model endpoint geography needs separate documentation.

### 6. Expand languages through a capability registry

Google currently lists 130 languages for Flash TTS and 101 for Flash-Lite TTS. Those are model capabilities, not this pipeline's validated coverage. Add a searchable registry with distinct source transcription, target synthesis, alignment, subtitles, and tested-quality status. Use labels such as Tested, Experimental, and Subtitles only only where each capability exists.

Spanish is the best next audition candidate because voice experiments already exist. Follow with user-relevant languages after alignment and native review. Keep the default demonstration small: EN/JA/ZH, then Spanish after verification. Display broad model potential separately. Source detection currently uses script heuristics; it needs redesign before claiming universal source-language support.

## Deck and submission changes

Keep the template but make every section support the same product story. The current benchmark PDF is legible; its main problem is the meaning and provenance of the numbers.

- Idea/USP: timing-aware translation, consent-aware casting, inspectable repair.
- Process: show one actual failed segment and its repair decisions.
- Screenshots: use the same dated run as the benchmark. Existing captures and reports show different line counts/runtime.
- Architecture: shared preprocessing, bounded language fan-out, checkpoints, partial results, and recovery. Separate deployed components from proposed improvements.
- Benchmark: include sample size, languages, model/version, date, execution environment, first-pass and final model-check results, unresolved flags, silence and alignment, listener results, time, cost assumptions.
- Cost: separate measured token charges, estimated infrastructure, and competitor retail prices. Remove unsupported claims that competitors are “open-loop”. Do not call a retail-price/marginal-cost ratio a product price advantage.
- Competition: [YouTube currently documents](https://support.google.com/youtube/answer/15569972) Korean-to-English/Indonesian and no editing of automatic dubs. It also supports expressive speech for some language pairs. Avoid the blanket claim that its voice never resembles the original.
- Roadmap: verify whether public YouTube APIs support uploading alternate audio tracks before promising one-click publication. Exporting a Studio-ready kit is the current useful boundary.
- Consent/privacy: describe retained embeddings, local recordings, provider voice profiles, and output retention separately. “Never stores audio” is too broad without an end-to-end audit.
- Final links: public repository and real accessible demo video, with no placeholders. Repository publication, video upload, deployment, and submission still need review/approval.

Suggested revised short-description direction: “VibeRick Dub helps creators review multilingual dubs in their own consented voice. Chirp provides word timing; Gemini translates for duration, synthesizes speech, checks each line, and repairs or flags problems. Firebase hosts the studio, Firestore streams progress, and Cloud Run executes the API and jobs.” Add only the improvements that have actually shipped and verified measurements at submission time.
